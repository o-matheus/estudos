## Principais conceitos

### Protocolos e comunicação

Um protocolo define regras de comunicação: como a interação começa e termina, como as mensagens são estruturadas e como são tratadas.

| Protocolo | Nome | Papel apresentado |
| --- | --- | --- |
| HTTP | Hypertext Transfer Protocol | Troca de requisições e respostas entre cliente e servidor web. |
| FTP | File Transfer Protocol | Transferência de arquivos. |
| SMTP | Simple Mail Transfer Protocol | Envio de e-mails. |
| TCP | Transmission Control Protocol | Transporte confiável e ordenado de dados. |
| UDP | User Datagram Protocol | Transporte de datagramas sem garantia própria de entrega ou ordem. |
| IP | Internet Protocol | Endereçamento e encaminhamento de pacotes entre redes. |

O professor relacionou hipertexto a documentos com referências para outros documentos, acessados por links. Uma precisão: esses documentos são conteúdo que pode ser transferido; HTTP é o protocolo de comunicação, não o documento em si.

A comunicação envolve diferentes camadas. No exemplo introdutório, HTTP define a troca de mensagens da aplicação, TCP transporta os dados e IP permite endereçar e encaminhar os pacotes. Isso não significa que todo HTTP use TCP: HTTP/3 utiliza QUIC sobre UDP.

### TCP e UDP: benefícios e custos

Na analogia do telefone sem fio, as crianças repassam uma mensagem sussurrada sem um mecanismo de conferência, e a informação original pode mudar até chegar ao final. O conteúdo transmitido é o *payload*. As crianças representam intermediários na analogia, sem serem literalmente proxies de rede.

TCP oferece mecanismos de detecção de perdas, confirmação, retransmissão e ordenação. Esperar dados perdidos pode aumentar o atraso ou causar pausas. Sua confiabilidade não garante sucesso diante de qualquer falha: a conexão ainda pode ser interrompida.

UDP envia datagramas sem oferecer, por si só, confirmação, retransmissão ou ordenação. A aula citou jogos e chamadas de vídeo como contextos em que receber informações recentes pode ser mais importante do que esperar informações antigas.

No exemplo de um jogo, um personagem pode parecer saltar de uma posição para outra após um problema de conexão. Interpolação, previsão e correção de posição são mecanismos da aplicação, não do UDP. Em uma chamada, perder alguns quadros pode ser tolerável; perdas maiores podem prejudicar a compreensão e exigir repetir informações.

### Iniciar o servidor local

O comando `next dev` inicia o servidor de desenvolvimento. Como o Next foi instalado no projeto, seu executável não fica necessariamente disponível como um comando global.

No `package.json`, o script foi configurado assim:

```json
"scripts": {
  "dev": "next dev"
}
```

Para executá-lo:

```sh
npm run dev
```

O npm disponibiliza os executáveis locais ao rodar scripts. A porta padrão apresentada foi `3000`, com acesso local por `http://localhost:3000`.

Na sequência da aula, a primeira tentativa ainda não funcionava porque faltava criar a estrutura de páginas. Essa falha inicial fazia parte da construção do projeto.

### Rotas baseadas em arquivos no Next.js

A aula usou o **Pages Router**, com rotas definidas pela estrutura de arquivos em `pages/`:

| Arquivo de exemplo | Rota |
| --- | --- |
| `pages/index.js` | `/` |
| `pages/produtos/index.js` | `/produtos` |

O termo é roteamento, não paginação: trata-se de associar URLs às páginas da aplicação.

O professor citou outra estrutura, baseada em `app/`, que estava em beta no contexto da aula. **Complemento verificado:** o App Router tornou-se estável no Next.js 13.4, lançado em 04/05/2023. Ambos usam roteamento baseado em arquivos; o projeto do curso segue a estrutura `pages/` apresentada na aula.

### Next.js e React

Na divisão introdutória de responsabilidades, o Next.js fornece a estrutura do servidor e das rotas, enquanto o React descreve a interface por componentes. Essa divisão é uma simplificação didática: Next.js também participa da renderização e integra o React.

Exemplo apresentado no relato:

```jsx
function Home() {
  return <h1>teste</h1>;
}

export default Home;
```

O conteúdo retornado usa JSX, uma sintaxe parecida com HTML. `export default Home` identifica o componente exportado como padrão da página, mesmo que o arquivo contenha outras funções.

### URL pública para o servidor local

O relato descreve o encaminhamento de porta pelo painel **Ports** do VS Code:

1. Usar **Forward a Port** e autenticar com GitHub, se necessário.
2. Informar a porta do servidor, neste caso `3000`.
3. Usar o link gerado; com visibilidade pública, ele pode ser acessado por outras pessoas sem autenticação.

O estudante testou o acesso pelo celular e confirmou que funcionou. A aula também demonstrou a atualização da página durante o desenvolvimento.

Esse acesso depende do servidor local e do túnel continuarem ativos, com o computador ligado e conectado. Não equivale a hospedar a aplicação de forma independente da máquina local.
